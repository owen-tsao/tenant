## Build a room performance

Jay's idea, October 17: compose an impromptu performance by adding devices as the conversation develops.

1. Say, “Can you start a beat on my computer?” Demonstrate a rhythm such as “dum, dum, dum, dum.”
2. Let the beat continue and ask for a change to it.
3. Say, “Sync my phone flashlight with that.” The phone joins the performance.
4. Ask for a matching visual on the computer, then show it through the projector if connected.
5. Keep developing the performance naturally through conversation.

The appeal is that each request builds on the last: the agent understands “that” and brings another device into the same activity.

**What works today:** computer speech, prepared music playback and pause, and a phone flashlight controlled through guest chat have physical test evidence. These do not establish beat generation or synchronization.

**What this idea needs:** a small test of rhythm input and generated playback; a common timing source for audio, light and visuals; a measured check that the phone remains visibly in time. Repeated model requests for individual flashes would not establish synchronization. The projector's connection and output remain untested.

**Smaller version to consider:** generated beat plus a matching computer visual, with the phone added only if its timing passes. Project the same computer output only after the connection works. This is a possible fallback, not a decision.

## Conversation rules for the demo

Use one visible room chat. Everyone who scans the public QR may receive temporary broad computer access, as Jay requested. Each new guest starts with fresh working context: previous guest requests and pending commands must not carry over. The exact reset and interruption behavior must pass before this becomes the live guest path.
